# Shinkou Insight 智能体 Harness 与安全计划

## 目标

把模型、工具、提示词、检索、租户隔离和审计放进同一条可验证的运行链路。所有外部模型调用都必须经过运行时配置校验；所有工具调用都必须经过权限、审批、超时和预算控制；所有输出都必须经过结构化校验、引用校验和脱敏。

## 已实现的基线

1. 模型设置分为常规设置和默认折叠的高级设置。高级参数包括 Temperature、Top P、Top K、最大输出、上下文窗口、频率/存在惩罚、随机种子、停止序列、推理强度、结构化输出方式和供应商扩展参数。
2. 模型配置会由 Java 后端解密并以受控运行时协议传给 AI Service，AI Service 使用 Pydantic 再次校验，并将采样参数传给 OpenAI-compatible Chat Completions/LangChain。
3. Agent 节点不再用固定温度覆盖模型配置；检索 Top K 与生成 Top K 使用不同字段，避免语义混淆。
4. Harness 默认执行本地确定性用例：提示词注入边界、引用完整性、写操作确认、工具预算、租户边界、模型参数边界、秘密脱敏和 SSRF 阻断。
5. 真实模型抗注入探针默认跳过，管理员主动勾选后才调用配置的项目模型；该模式明确标记可能产生模型费用。
6. Harness 运行、单条结果和审计事件写入数据库，只有工作区管理员可启动，成员可查看结果和审计历史。

## 每次运行的安全门

```text
请求身份/工作区权限
        ↓
项目范围校验 → 运行时配置 Pydantic 校验 → 工具权限/审批/预算/超时
        ↓
不可信内容隔离 → 模型调用 → 结构化输出校验 → 引用 ID 白名单
        ↓
秘密脱敏 → 最小化证据落库 → 审计事件
```

## 验收标准

- 无模型或未勾选探针时，Harness 不访问外部模型；8 个本地安全用例全部通过。
- 任意越界采样参数、跨项目 ID、未确认写操作和内网 URL 都会被拒绝。
- 审计结果不出现 API Key、Token、密码或原始凭证。
- 同一配置连续运行能得到可比较的用例状态、得分和失败证据。
- 前端高级配置默认未挂载；只有用户点击“展开”后才创建高级控件并参与提交。

## 后续增强

- 将工具调用策略（最大调用次数、审批模式、自治级别）从工作区设置进一步注入每次运行，而不是只使用服务默认值。
- 增加基于固定数据集的离线质量评估：答案正确性、引用精确率/召回率、拒答率、工具轨迹和成本预算。
- 接入定时 Harness、版本对比、回归阈值和导出报告；模型/Prompt/工具变更未通过基线时阻止发布。
- 对允许访问的网络目标使用出口 allow-list，并在 DNS 解析后重新校验最终 IP，防止 DNS rebinding。
