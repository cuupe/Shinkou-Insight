# 09. 项目讲解、120 个面试问题与复习路线

所有回答以当前实现为边界；没有实测的吞吐、准确率和节省比例不填数字。下面是组织答案的示范，不是需要逐字背诵的台词。

| 岗位 | 优先讲 | 面试官通常继续挖 |

## 2. 三种长度的项目介绍

### 30 秒

我做的是一个面向团队的证据驱动调研平台。用户把资料放进工作区和项目，系统解析、切片和检索，再由受预算约束的 Agent 形成有引用的报告，并进入审查和行动项闭环。Vue 提供工作台，Java 管用户权限和业务数据，Python 管模型、RAG 和工具；PostgreSQL、Milvus、Redis 和 MinIO 各自承担业务事实、向量、任务状态与文件存储。

### 3 分钟

先讲业务问题：企业资料分散，模型直接回答难解释。我的目标是让结论能回到具体资料，证据不足和冲突明确可见。

再讲一条完整链路：用户上传文件，Java 验证项目权限和配额、保存对象和资产；事务提交后再派发 Python，避免独立连接看不到资产。Python 解析、按章节和自然边界切片，把正文放 PostgreSQL、向量放 Milvus。检索结合关键词与向量，用 RRF 融合，再生成带证据的回答。

然后讲工程控制：Agent 的工具、次数、时间、租户和输出格式由代码约束，前端通过 SSE 看过程，并以快照补偿断线。Redis Streams 支持任务回收，长任务用心跳防误回收，但我不把它夸成分布式恰好一次。

最后讲验证和边界：仓库有自动测试及 Docker 基础冒烟记录，真实模型质量需要固定数据集单独评估。当前会话仍在 JVM，主执行是语义决策 Runtime，LangGraph 图是兼容路径；多实例和零停机索引还有明确演进空间。

### 10 分钟顺序

业务与不变量 1 分钟 → 架构与数据归属 1 分钟 → 上传/索引事务 2 分钟 → 混合检索与引用 2 分钟 → Agent/队列/SSE 2 分钟 → 验证、故障与演进 2 分钟。每段至少准备一张图、一处代码和一个反例。

## 3. 前端与浏览器：Q01—Q10

### Q01. Vue 的响应式到底做什么？

答：建立状态与使用它的计算/渲染之间的依赖，变化后调度相关更新。项目把运行状态放在 composables 中，再由组件展示。还要说明 computed 是派生值、watch 处理副作用，以及整体替换、解构和生命周期对响应式的影响。

### Q02. 为什么现在不说「项目用 Pinia 管全部状态」？

答：依赖声明了 Pinia，但 main.ts 没有注册 createPinia，当前业务主要是 Composition API。可以讨论未来在跨页面共享状态上接入 Pinia，但要和已经完成的实现分开。

### Q03. Vite 转换 TypeScript 后为什么还要 vue-tsc？

答：快速转换为可运行代码与完整类型检查不同。当前 build 并行进行 type-check 和构建，类型检查约束组件和 API 使用，但运行时异常和错误 JSON 仍需业务校验。

### Q04. 路由刷新为什么会 404？

答：History URL 是前端路由，服务器可能把它当真实文件路径。当前 Nginx try_files 回退 index.html，再由 Vue Router 匹配；API 要独立匹配，避免错误返回 HTML。

### Q05. 如何避免慢请求覆盖新项目数据？

答：取消旧请求、记录请求版本、写状态前核对 workspace/project，并按身份和项目分区缓存。仅取消不够，因为请求可能已经完成或底层不支持取消。

### Q06. 前端所有错误都跳登录合理吗？

答：不合理。401 才说明当前请求未认证；502/503/504 可能只是后端短暂故障。request.ts 区分二者，并合并一段时间内的认证失败处理，避免重定向风暴。

### Q07. 为什么数据库 ID 在前端用字符串？

答：BIGINT/long 可能超过 Number 安全范围，JSON 解析阶段就会丢精度。协议应传字符串，排序游标时用 BigInt；先解析成 Number 再转字符串不能恢复。

### Q08. async 函数为什么仍让页面卡？

答：async 不会自动创建工作线程。Markdown、代码高亮、公式和大列表过滤仍占主线程；应减少重复、批量更新、缓存或使用适当 Worker，并用 Performance 证据定位。

### Q09. 为什么路由守卫不是安全边界？

答：攻击者可以绕过 UI 直接请求 API。后端必须查成员、项目和资源归属，检索、缓存和对象下载也要同样限制。守卫主要改善导航和错误体验。

### Q10. Markdown 安全怎么做？

答：把模型和文档输出都当不可信文本，控制 HTML/链接并在渲染链正确清洗。DOMPurify 依赖存在不说明每个 v-html 都安全；流式中间态还要保护未闭合代码围栏，避免误解析。

## 4. HTTP、会话与 SSE：Q11—Q20

### Q11. CORS 与 CSRF 有什么区别？

答：CORS 限制浏览器跨源读取/发起特定请求的方式；CSRF 针对浏览器自动附带身份的伪造写请求。二者都不替代认证和授权，服务端脚本也不受浏览器 CORS 约束。

### Q12. JSESSIONID 和 XSRF-TOKEN 为什么一个 HttpOnly 一个不是？

答：登录凭据不需要 JS 读取，所以会话 Cookie 为 HttpOnly；CSRF Cookie 需要前端取出后写请求头，允许脚本读。二者目的不同，不能把所有 Cookie 的设置混用。

### Q13. 为什么 CSRF 初始化用共享 Promise？

答：首次多个写请求同时触发时复用一次 /auth/csrf，避免并发 token 初始化和重复请求；finally 清理使失败后能重新尝试。独立客户端还避免拦截器递归。

### Q14. 当前认证是 JWT 吗？

答：不是。实际使用 HttpSessionSecurityContextRepository 和 JSESSIONID，SessionRegistryImpl 维护会话控制。Redis 被其他功能使用，不代表接入了 Spring Session。

### Q15. 为什么 SSE 适合这个产品？

答：进度主要单向由服务器推送，创建/取消走 HTTP，SSE 满足需求且易与同源 Cookie 结合。WebSocket 更适合持续双向协议，但一样需要鉴权、重连和消息语义。

### Q16. EventSource 重连是否保证不丢不重？

答：不保证。必须保存事件 ID、服务端支持游标回放、前端去重，并用最终快照校准。当前 agentStream 同时轮询快照，有界保留去重 ID，终态用完整内容覆盖。

### Q17. 为什么 SSE 断线不能重新调用创建接口？

答：断的是观察通道，后台可能仍在调用付费模型。应重连已有 runId 并拉快照；重新创建会重复任务和费用。只有用户明确重试才创建新 Run。

### Q18. Nginx 为什么让流式输出积成一块？

答：响应缓冲可能先积累再转发，当前配置关闭 proxy_buffering 和 cache、延长流连接超时。还需检查应用是否 flush、Provider 是否真实流式及中间层压缩/缓冲。

### Q19. 前端 10 秒超时与后台长任务冲突吗？

答：长任务接受请求应尽快返回运行标识，后续用 SSE/快照读取，不让普通请求一直等待。各层 timeout 约束不同阶段，不能把所有值调大当作可靠性方案。

### Q20. 关闭页面是否应该取消运行？

答：通常不应，用户可能只刷新或切设备。页面卸载清理本地订阅与定时器；业务取消通过独立接口改变运行状态，并承认外部已发生的调用未必能撤销。

## 5. Java / Spring / 并发：Q21—Q30

### Q21. 单例 Service 是否线程安全？

答：单例只说明复用实例。方法参数和局部变量通常不互相共享，但可变成员、缓存和集合需要并发设计。不能把当前用户保存在单例字段中。

### Q22. @Transactional 为什么可能不生效？

答：代理调用才有拦截；同类 this 调用可能绕过，方法可代理性也影响。还要看异常是否符合回滚规则，事务管理器是否正确，外部线程是否已离开事务上下文。

### Q23. 为什么资产索引放 afterCommit？

答：Python 用另一数据库连接，Java 未提交时它看不到资产，可能插 Chunk 外键失败。afterCommit 保证已提交可见，又避免外部调用占住原事务。

### Q24. afterCommit 后一定不会丢任务吗？

答：不会有这个保证。提交后到派发前进程可以崩溃。可靠派发可用事务 Outbox，把待发任务与资产同事务提交，再由派发器重试；当前没有完整 Outbox。

### Q25. 虚拟线程为什么有用？

答：索引和 AI HTTP 调用常等待 I/O，虚拟线程降低大量等待任务的线程组织成本。但 CPU、数据库连接、Provider 限额不增加，仍需并发上限和生命周期管理。

### Q26. synchronized 为什么不能解决多实例重复处理？

答：只协调一个 JVM 的线程。另一个实例有自己的锁和内存；需要数据库条件认领、共享租约/消息协调和幂等提交，不能依赖本地集合。

### Q27. MyBatis 的 #{} 和字符串拼接有什么差别？

答：#{} 绑定值，避免把值当 SQL 结构；动态表名、排序字段等结构仍需白名单。参数绑定防注入不代表查询规模被限制，LIMIT/范围和执行计划仍要控制。

### Q28. 存储配额怎样避免并发超额？

答：在事务内锁用户统计行，读额度、检查并更新，或采用原子条件更新。文件与计数跨系统，还需要失败补偿与对账；单纯「先查后写」有竞态。

### Q29. Snowflake worker 随机分配是否严格唯一？

答：不是，只降低相撞概率。当前是单节点用途设计，多进程需明确 worker 分配、时钟回拨与重启行为。还要处理数据库序列混用和前端精度。

### Q30. GC 很频繁你会先改参数吗？

答：先确认分配速率、存活对象、堆外内存和容器限制，找大文件、事件集合、SSE 未释放等保留原因。参数调整应基于 GC 日志/JFR，不能掩盖对象泄漏或无界增长。

## 6. PostgreSQL：Q31—Q40

### Q31. 项目数据模型最重要的关系是什么？

答：用户经 workspace_members 进入工作区，项目属于工作区，资产/运行/报告属于项目。还有线程、消息和运行的关系。任何查询必须沿正确关联验证授权，不能只信一个 ID。

### Q32. 为什么要数据库唯一约束？

答：应用预检查挡不住两个并发请求同时认为不存在。手机号、成员关系、消息幂等键和报告来源行动项应由唯一约束兜底，再把冲突转换成可理解结果。

### Q33. 给一个实际的部分索引例子。

答：notifications 只索引 read_at IS NULL 的未读数据；action_items 仅在来源报告/来源键非空时强制唯一。部分索引减少无关数据，查询条件还需匹配其谓词。

### Q34. 有 GIN 为什么关键词查询还慢？

答：生产 SQL 包含物化候选和计算排名，未必有能使用 GIN 的 @@ 过滤；中文子串也可能扫描大量候选。需要实际 EXPLAIN，不能只依据建过索引。

### Q35. PostgreSQL 默认隔离级别保证什么？

答：Read Committed 防脏读，每条语句有已提交快照，同一事务两次读可能不同。额度等跨语句不变量要用锁或条件更新，不能交给默认隔离自动保证。

### Q36. PostgreSQL Repeatable Read 会幻读吗？

答：PostgreSQL 的实现避免幻读，但仍可能存在序列化异常；不能照搬其他数据库的简单表格。Serializable 更强但可能失败，需要事务重试和副作用控制。

### Q37. 连接池越大越好吗？

答：不。池过大可能让数据库并发过载；过小会排队。要计算 Java 与 AI 全部副本连接总和，观察借连接等待、查询/事务时间及数据库资源后调整。

### Q38. 为什么用 JSONB 又保留关系表？

答：配置、事件和快照结构变化多，JSONB 合适；核心关系、状态和高频过滤仍用明确列与约束。全部塞 JSONB 会让授权、迁移和查询优化更难。

### Q39. Flyway 校验失败可以直接 repair 吗？

答：先查文件变更和环境漂移。已执行迁移通常应追加版本而非改写；repair 会修改元数据，不能代替确认真实 schema 与历史一致性。

### Q40. 为什么 Docker volume 不是数据库备份？

答：同一数据卷可被误删、损坏或随磁盘丢失。备份需独立保存并实际恢复验证，数据库之外还需业务对象、加密密钥和模型/索引版本。

## 7. 文档、Embedding、RAG：Q41—Q50

### Q41. 为什么不固定每 1000 字切一次？

答：事实可能跨边界，标题和限定条件会丢。当前默认 natural 1200 字符、overlap 180，保留章节；仍要按语料评估，不是任何资料都用同一个最佳值。

### Q42. Chunk 长度是 Token 吗？

答：当前 splitter 的长度按字符语义，不能说固定 Token。输入模型前还需 Token 预算，中文、英文和代码的字符/Token 比例不同。

### Q43. 默认 hash Embedding 有什么用？

答：确定性、无需外部凭据，适合连通与测试，不证明语义理解。当前适配器遇到 hash 会把向量/混合有效模式降为关键词，真实语义检索需外部模型和重建。

### Q44. 两个 Embedding 模型维度相同能混用吗？

答：不能据此认为兼容。维度只限定长度，语义空间、归一化和版本可能不同。要为模型版本做指纹和索引隔离，再通过质量评估切换。

### Q45. 关键词和向量为什么要融合？

答：关键词擅长型号、文件名、精确术语，向量擅长语义近似。原始分数尺度不同，当前用 RRF/加权 RRF 等组织候选；两路好坏仍要分别评估。

### Q46. RRF 公式说明一下。

答：候选得分是各通道权重除以常数加排名后的和。当前默认 k=60，权重 0.55/0.45。它弱化分数尺度差异，但忽略原始分差，参数效果应以固定集验证。

### Q47. 当前 Reranker 是大模型吗？

答：不是，LexicalReranker 用词命中、短语和融合分确定重排。成本低、可重复，但同义词/跨语言可能误删；Cross Encoder 是扩展方案。

### Q48. 为什么要在 PostgreSQL 二次查向量命中？

答：Milvus 主要返回索引 ID 和分数，正文与业务归属在 PostgreSQL。回表时再次校验租户、项目和资产状态，减少残留向量导致越权或过期正文的问题。

### Q49. 引用 ID 存在就说明回答可信吗？

答：还要查引用归属、Quote 是否在 Chunk、断言是否被支持、主体/时间/单位是否匹配。数字碰巧在某证据出现也不证明事实正确，规则和人工/模型标注需结合。

### Q50. 检索失败为什么不先换大模型？

答：先看解析、切片、资产状态、模型是否 hash、范围、召回、融合、重排和上下文截断。没召回关键事实时，生成模型通常无法从空上下文恢复可信证据。

## 8. Agent 与评估：Q51—Q60

### Q51. 当前 LangGraph 在主链路吗？

答：qa_graph.py 明确是 legacy，主 Runtime 进入 _execute_semantic 和 DecisionEngine。代码还保留协调器/角色总线；应按实际调用图讲，不能照背早期文档。

### Q52. 为什么不做完全自主 Agent？

答：企业任务需要成本、权限和证据边界。模型可以选择动作，但次数、时间、工具、租户和输出规则由代码检查；预算耗尽应整理已有事实并报告缺口。

### Q53. 多 Agent 一定更好吗？

答：不会自动更好。职责隔离和并行独立子问题有价值，也增加输入重复、延迟与故障路径；同一模型角色可能共享偏差，要在同预算下比较任务质量。

### Q54. 工具白名单能解决什么？

答：限制模型可调用能力，但不能替代参数作用域、用户写权限、确认和副作用幂等。合法工具也可能被用于访问错误项目，必须继续验证资源。

### Q55. Pydantic 成功为什么还可能错？

答：它验证结构与类型，不证明事实、租户和引用语义。一个符合 Schema 的错误金额或假引用仍需证据和业务校验。

### Q56. Reflection 怎样避免无限修订？

答：复核/修订共享决策、时间和 Token 预算，限制次数，并记录发现问题和修订结果。超过边界应明确限制或失败，不能为了通过审查不断自我改写。

### Q57. 如何证明 Prompt v2 优于 v1？

答：固定模型/参数、语料、检索、数据集和预算，分别测任务成功、引用、结构化输出、延迟和成本。保留负例和原始结果，避免只展示几个精选答案。

### Q58. Recall@K 和引用正确率区别？

答：Recall 衡量检索找回标注证据的比例；引用正确率衡量答案引用是否真的支持断言。召回好也可能生成错，用对引用也可能遗漏关键事实，需要分层看。

### Q59. 为什么不微调模型记住企业资料？

答：资料变化与权限隔离更适合 RAG，更新、删除和溯源更直接。微调可改善稳定窄任务或输出风格，但不能替代实时知识、权限和引用机制。

### Q60. 项目有 QLoRA 成果吗？

答：当前材料是可选实验设计，没有证据就不说已训练上线。若开展，应以证据分类为窄任务，固定 Prompt 基线并比较 Macro-F1、冲突召回、延迟和成本。

## 9. Redis 与任务可靠性：Q61—Q70

### Q61. 为什么用 Redis Streams 不直接开后台线程？

答：需要跨请求排队、消费组、Pending 和崩溃回收；本地线程只随当前进程存在。Streams 仍需幂等、保留策略和监控，不是自动可靠全部步骤。

### Q62. XACK 是否删除消息？

答：它确认消费者组中的 Pending，不直接等于删除 Stream 记录。消息裁剪和未完成任务保留需另外设计，否则日志增长或过早裁剪都会有问题。

### Q63. XAUTOCLAIM 为什么可能导致重复模型调用？

答：回收基于 idle，而正常模型可能运行超过阈值。当前 30 秒回收配 10 秒心跳刷新所有权，避免活跃任务被误判；网络抖动下仍需幂等。

### Q64. 已有 _active_runs 为何还不够？

答：它只在一个 Python 进程有效。两个进程同时执行同 runId 需要共享原子认领/租约和终态条件更新，本地集合不能证明全局唯一执行。

### Q65. 所有任务失败都会自动重试三次吗？

答：不是。handler 异常会触发队列尝试；Runtime 对预期模型/工具失败保存终态后正常结束，避免整轮自动重复计费。显式重试创建新 Run。

### Q66. Redis 快照是否等于从中断节点继续？

答：快照能恢复可读状态，不会自动恢复协程栈、工具副作用和精确执行位置。精确续跑需要步骤收据、检查点和幂等副作用，当前不应夸大。

### Q67. Redis 不可用回退内存好吗？

答：开发方便，但重启恢复和跨进程保证降低。生产要决定哪些职责允许降级、哪些必须拒绝新任务，并把实际模式暴露给运维/用户。

### Q68. AOF 开了是不是零丢失？

答：还取决于 fsync、存储和故障时点，不能做零丢失承诺。备份、复制和恢复演练仍需要；当前没有 Sentinel/Cluster 高可用部署。

### Q69. 缓存击穿现在怎样处理？

答：CacheService 的 get_or_set 用同进程按键 asyncio.Lock 合并加载。跨进程仍可各自重建，若成为热点要增加受控分布式协调或提前刷新，同时避免锁泄漏与超时。

### Q70. 为什么缓存和任务放一个 Redis 有风险？

答：内存、CPU、持久化和故障域共享；可丢缓存的淘汰策略可能误伤关键任务/快照。可拆实例或明确资源/策略，逻辑 DB 不能隔离这些风险。

## 10. Docker 与数据基础设施：Q71—Q80

### Q71. 为什么前端镜像不运行 npm run dev？

答：生产只需要构建产物和静态服务器，Node 构建依赖无需进入运行镜像。Nginx 同时负责 SPA 回退和 API 代理，开发服务用于本地调试。

### Q72. Docker build 成功为什么不能说测试通过？

答：Java Dockerfile 显式 -DskipTests，AI 镜像也不执行完整 pytest。构建验证依赖和产物，自动测试、运行连通和真实业务是不同证据。

### Q73. depends_on 为什么加 condition？

答：进程启动不等于服务准备好。service_healthy 等探针，service_completed_successfully 等初始化完成；运行中依赖失效仍需要客户端恢复。

### Q74. 容器访问 localhost:15432 为什么失败？

答：容器 localhost 是自身，15432 是宿主映射。backend/AI 应访问 postgres:5432。浏览器、本机开发进程、容器具有不同地址视角。

### Q75. 用不同 -p 启动测试栈一定隔离吗？

答：当前网络和卷有显式固定 name，不会全部随项目名变化。隔离 QA 需要覆盖卷/网络与端口，核对解析结果，不能只看容器名前缀。

### Q76. 为什么有两个 MinIO？

答：业务 MinIO 存上传和生成物，Milvus MinIO 存向量引擎内部对象，职责和数据卷不同。业务代码不应随便删 Milvus 的底层文件。

### Q77. etcd 是拿来存向量吗？

答：不是，存 Milvus 元数据/协调信息。它重视一致性；当前单节点没有多节点容错。清空 etcd 不能当作普通重启，会破坏与对象数据的对应关系。

### Q78. 当前 Milvus 是 HNSW 吗？

答：源码配置 AUTOINDEX + COSINE + Bounded，不应说手调了 HNSW 参数。可以解释 HNSW/IVF 的原理和取舍，但要标明不是当前配置。

### Q79. Neo4j 容器运行就一定在使用吗？

答：GRAPH_MODE 默认 memory，容器启动和应用 Provider 选择不同。Neo4j 没有 profile，完整 up 可能启动它，但仍需配置图模式才选用对应适配器。

### Q80. MCP 服务开起来为什么工具仍不可用？

答：还需要 AI MCP_ENABLED、URL、API Key、允许工具与协议调用成功。复用镜像的 Uvicorn 探针已禁用，不能仅凭容器 running 判定 MCP 健康。

## 11. 安全、性能与运维：Q81—Q90

### Q81. 多工作区隔离只加 workspace_id 条件够吗？

答：还要校验 project 与 workspace、资源与 project、用户与成员关系，并覆盖索引、缓存、对象和图谱。路径各 ID 分别存在不代表它们相互匹配。

### Q82. Prompt Injection 怎样防？

答：不把文档/网页指令升级为系统策略，模型无权改变租户、凭据和工具集；注册表、作用域、预算、确认和副作用审计由程序执行。关键词过滤不足以构成完整防御。

### Q83. 当前 URL 校验彻底防 SSRF 吗？

答：不是。它拒绝部分内部域名与私有 IP 字面量，但明确不解析 DNS。还要在连接和每次重定向中校验最终地址，配合 egress 限制，才能处理更多绕过。

### Q84. AES-GCM 密钥换了会怎样？

答：旧凭据可能无法解密。要稳定保管主密钥，轮换时带版本/兼容解密与重加密流程；Base64 不是加密，数据库备份也不能替代密钥备份。

### Q85. API 慢会先看什么？

答：分段看排队、连接池、SQL、工具和模型，区分首响应与总耗时，再看分位和错误原因。直接增加线程/连接可能把瓶颈转移并放大下游压力。

### Q86. 如何估算 8 个 Worker 是否够？

答：结合到达率、任务占用时长、Provider 并发和队列等待。可用在途数≈到达率×平均时长做初估，再压测；协程能等待不意味着外部资源无限。

### Q87. 为什么说 P95 而不是只说平均延迟？

答：少数长任务会严重影响用户，但均值可能掩盖尾部。还应按任务类型、缓存命中和 Provider 分组，避免把快的 mock 与真实长研究混在一起。

### Q88. 镜像回滚是否就能回滚系统？

答：数据库 schema、加密格式、事件协议和已发生外部副作用可能不兼容旧镜像。要设计兼容迁移、备份和补偿；回滚必须验证实际数据语义。

### Q89. 什么叫恢复验证成功？

答：在独立环境恢复后，用户权限正确、原文件可读、报告可追溯、检索可用、任务终态合理，并核对数据缺口和耗时。仅启动进程或 pg_restore 无错误不够。

### Q90. 你如何报告已有测试？

答：引用日期与范围。2026-10-18 记录的前端/Java/Python 通过数及跳过数都应说清；Docker 用 mock，未做真实模型完整研究。通过数不等于覆盖率，本次文档任务也未重跑它们。

## 12. 系统设计与行为问题：Q91—Q100

### Q91. 最值得讲的技术难点是什么？

答：选自己有代码证据的一项，如事务提交与异步索引可见性、长任务 Pending 误回收、SSE 与快照协调。说明触发条件、根因、实现和验证，不把普通 CRUD 包装成高并发难题。

### Q92. 如果只能保留三个亮点？

答：端到端证据链与审查闭环；Java/Python 边界及多租户控制；长任务的事件、快照、队列和预算。每个亮点都准备实现与局限，而不是罗列十几个库名。

### Q93. 如果删掉 Milvus 会怎样？

答：可讨论用 PostgreSQL 向量扩展或内存实现降低运维，但资源隔离和扩展方式改变，也需重写索引/检索适配。先明确规模与质量约束，不以组件多少判断优劣。

### Q94. 下一步最先补什么？

答：按目标选。如果要多实例上线，先处理共享会话、Run 认领、事件和取消传播；如果要证明 AI 价值，先固定真实模型评估集。不要先为了技术展示增加更多 Agent。

### Q95. 如何解决 PostgreSQL 与 Milvus 双写？

答：当前失败标记与可重建索引是一种实用边界；更可靠可用版本化 Chunk/Collection、active version 切换、Outbox/重派和对账。不能声称本地 @Transactional 能覆盖 Milvus。

### Q96. 报告引用会因重新索引失效吗？

答：当前重建替换 Chunk 可能改变 ID，因此历史引用稳定性需要证据快照或版本化 Chunk。要区分展示旧引用文本与实时定位原 Chunk，不能默认二者永远一致。

### Q97. 怎样证明自己真的做过？

答：现场从页面请求找到 Controller、Service、Mapper，再到 Python 运行与向量/文件位置；修改一个测试条件复现已知边界，展示日志和结果。能解释失败路径比只展示顺滑 demo 更有说服力。

### Q98. 怎么回答没有高并发实测？

答：直接说尚未做该量级认证，给现有测试范围、容量估算和压测计划。可以说明理论限制和预计瓶颈，但不把估算写成已经达到的 QPS。

### Q99. 技术取舍做错了怎么办？

答：说明当时约束、观察到的新证据、影响和修正方案。例如早期图工作流适合明确节点，后续主执行调整到受约束语义决策；回答围绕实际原因和验证，不编造历史。

### Q100. 如果面试官指出旧文档和代码不一致？

答：以当前代码为准，说明旧材料的演进背景，现场核对调用链。主动指出 JWT/Redis Session、LangGraph 主路径、Pinia、BM25 和 Rerank 等差异，体现能管理事实边界。

## 16. 官方资料专项追问：Q101—Q120

这些题补充协议细节与版本边界，来源与章节对应关系见 [官方资料导航](11-official-references.md)。

### Q101. 为什么 onWatcherCleanup 不能放在 await 后？

答：该 API 要在 watcher 同步执行时登记清理，异步等待后不能再按同样方式注册。项目切换应尽早关联 AbortController，还要保护旧请求的 catch/finally，避免旧请求关闭新页面 loading。详见 [前端第 13 节](01-frontend.md)。

### Q102. SSE 加了 event 字段，onmessage 为什么没收到？

答：具名事件分发到对应类型，客户端需要 addEventListener；默认 message 才交给 onmessage。项目业务 type 目前在 JSON 内，改变传输 event 字段是协议变化，不能只改后端格式。详见 [前端第 14 节](01-frontend.md)。

### Q103. 手动创建新 EventSource 会继承旧游标吗？

答：不能这样假设。自动重连属于同一个对象的状态，手工重建要把保存游标传入服务支持的恢复入口；后端还要保留可回放数据。游标更不是用户处理结果的业务 ACK。

### Q104. proxy_send_timeout 控制向浏览器发 Token 吗？

答：它控制代理向上游发送请求的相邻写入等待；上游响应读取由 proxy_read_timeout 等约束，整轮研究另有业务预算。把 send_timeout 当 SSE 总时长会误诊故障。详见 [Docker 第 17 节](06-docker-nginx.md)。

### Q105. 内层 REQUIRED 异常吞掉后，外层一定能提交吗？

答：内外可能共享物理事务，内层标记 rollback-only 后，外层即使捕获异常也可能提交失败。应检查真实代理路径和事务标记，不能用 catch 代替事务语义。详见 [Java 第 15 节](02-java-backend.md)。

### Q106. 把内层改成 REQUIRES_NEW 有什么新风险？

答：它独立提交，也可能在外层占连接时再借一个连接；高并发下会增加池压力与等待。还要判断内层记录是否应该在外层失败时保留，而不是只为了绕过回滚而改传播。

### Q107. synchronized 一定会 pin 虚拟线程吗？

答：必须讲版本和是否发生阻塞。当前 Java 21 关注同步区内长等待，后续 JDK 已改善相关行为；短内存临界区不能直接等同于严重扩展问题。实际看 JFR 和调用栈，见 [Java 第 16 节](02-java-backend.md)。

### Q108. INCLUDE 了所有返回列为什么仍有 Heap Fetch？

答：索引具备数据还不够，MVCC 可见性可能要求访问堆；应看 visibility map 和执行计划。频繁更新表不宜仅凭覆盖列齐全就预测收益。详见 [PostgreSQL 第 14 节](03-postgresql.md)。

### Q109. UNIQUE 和 CHECK 都能阻止 NULL 吗？

答：不能按这个规则理解。默认唯一语义允许多个 NULL，CHECK 对 NULL 结果也不等同于失败，非空应另声明。项目来源部分唯一和配额非空/非负约束要结合业务解释。

### Q110. 并发建索引可以直接放进普通事务迁移吗？

答：PostgreSQL 不允许 CREATE INDEX CONCURRENTLY 在事务块中执行；还要处理等待和失败残留。迁移器执行模式与回退流程必须一起安排，不能只给 SQL 增加一个单词。

### Q111. FastAPI 会自动把所有 def 函数放线程池吗？

答：它对自己调度的同步路由/依赖有处理，async 路由里手工调用的普通辅助函数仍正常同步执行。解析器和 SDK 应沿实际调用点决定卸载，见 [Python/RAG 第 14 节](04-python-rag.md)。

### Q112. 为什么不把所有 gather 换成 TaskGroup？

答：先判断部分成功是否有价值。TaskGroup 的失败取消语义与 gather(return_exceptions=True) 不同；两路检索可以容忍一路失败，必须保留这个契约，并正确传播取消。

### Q113. 有 Pydantic int 字段就一定拒绝字符串吗？

答：默认可能转换，需要选择 strict 并核对输入方式。严格化也会改变已有客户端行为，所以先用字符串数字、布尔、空值与越界值做契约测试。详见 [Python/RAG 第 15 节](04-python-rag.md)。

### Q114. Pending 消息会被 Stream 裁剪保护吗？

答：不会自动保护 payload。当前 maxlen 可能裁剪未完成任务，PEL 留 ID 也不能恢复正文；所以要按积压与故障时间设计保留，并识别缺失正文。详见 [Agent 第 15 节](05-agent-evaluation.md)。

### Q115. XAUTOCLAIM 每次从 0-0 开始为什么值得检查？

答：单次扫描有界，若前面存在长期活跃 Pending，后面待回收项可能被延迟扫描。当前代码没推进返回游标，这是大 PEL 场景待验证的静态推导，不能说已经压测证实。

### Q116. 官方文档出现 ACKED/DELEX，能直接使用吗？

答：当前服务 Redis 7.4，latest 页面可能混有更新版本能力，必须核对 since；客户端包版本也不同于服务器版本。设计安全释放或裁剪要使用当前支持的命令组合。

### Q117. .env 改了为何容器变量没变？

答：先看 Compose 是否引用了这个值，再看 environment/env_file/镜像 ENV 及启动覆盖。常量配置不会因同名 .env 自动变化，已有容器也需按发布方式更新。详见 [Docker 第 16 节](06-docker-nginx.md)。

### Q118. 正确释放 Redis 锁能杜绝旧 Worker 覆盖吗？

答：它防误删他人锁，但租约过期后旧 Worker 仍可能继续返回结果。可用持久化 execution_epoch 与条件提交拒绝旧执行者；这仍不能撤销外部计费。详见 [数据系统第 11 节](07-data-systems.md)。

### Q119. MCP Streamable HTTP 一定有 Session ID 吗？

答：规范允许有状态会话，并非所有服务都分配；当前设置 stateless_http=True。还应分别核对协商版本、Origin、认证、端口发布和业务租户范围，见 [数据系统第 15 节](07-data-systems.md)。

### Q120. 三个实例的 P95 能取平均做全局 P95 吗？

答：不能，分位数要由合并后的兼容分布或样本计算。指标标签还应限制基数，runId 更适合 Trace/日志；当前是观测扩展设计，见 [可靠性第 15 节](08-reliability-security.md)。
