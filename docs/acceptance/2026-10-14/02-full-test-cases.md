## ENV 环境与基线

批次：01 准备。入口：启动脚本、服务日志、部署环境。

前置：隔离验收环境；先记录版本和环境，不使用现有业务数据做破坏测试。

### ENV-001 确定验收版本

优先级：P0。

操作：

1. 记录 commit、未提交变更摘要、构建时间、依赖版本和配置开关
2. 保存基线清单

预期：

- 测试报告能够唯一对应到代码与配置
- 测试中变更版本需重跑受影响用例

### ENV-002 基础设施启动

优先级：P0。

操作：

1. 按 README 启动 PostgreSQL、Redis、Milvus、MinIO
2. 查看 docker compose ps

预期：

- 必需容器 healthy
- 初始化桶成功
- 无持续重启

### ENV-003 三个应用启动

优先级：P0。

操作：

1. 运行 scripts/start-all.ps1 -NoBrowser
2. 访问前端、AI /health
3. 查看 Java 启动日志和认证接口

预期：

- 前端 HTTP 200
- AI status=ok
- Java 完成启动并连通数据库
- 受保护 health 返回 401 不计健康通过

### ENV-004 前后端代理

优先级：P0。

操作：

1. 通过前端访问 /api/auth/captcha
2. 对照后端 /auth/captcha

预期：

- 真实验证码接口成功
- 无 CORS 错误、代理 502 或路径重复 /api

### ENV-005 持久化重启

优先级：P0。

操作：

1. 记录项目、资料、运行、报告 ID
2. 正常重启应用后重新登录查询

预期：

- 数据库记录、文件与已完成结果保留
- 会话按既定策略恢复

### ENV-006 运行依赖可用

优先级：P1。

操作：

1. 在工具设置或内部 files/tools 查询 OCR、PDF、Office、音视频能力

预期：

- 状态反映真实工具
- 缺失依赖列为阻塞或明确不支持，不能显示已就绪

### ENV-007 真实模型配置

优先级：P0。

操作：

1. 记录本轮 LLM、Embedding、端点、模型版本
2. 执行连接测试与一次真实请求

预期：

- 不是 mock 模型
- 真实模型可调用
- hash 仅能证明流程，不代表真实语义检索质量

### ENV-008 测试环境隔离

优先级：P0。

操作：

1. 建立独立 QA 工作区和可销毁数据库/存储
2. 核对压测和故障注入目标

预期：

- 删除、配额、服务中断仅影响 QA
- 有恢复步骤与备份

### ENV-009 日志时间一致

优先级：P1。

操作：

1. 对比浏览器、Java、Python、数据库事件时间

预期：

- 事件顺序正确

### ENV-010 环境失败可解释

优先级：P1。

操作：

1. 故意缺少一项必需配置在独立实例启动
2. 随后恢复

预期：

- 清楚指出配置或依赖失败

### ENV-011 上线范围登记

操作：

## AUTH 注册、登录与会话

批次：02 账号。入口：登录页、注册页、找回密码弹窗。

前置：测试账号 A/B/C/D；独立浏览器配置；真实短信链路未接入时相关用例记阻塞。

### AUTH-001 图片验证码加载与刷新

优先级：P1。

操作：

1. 打开登录/注册
2. 刷新验证码
3. 提交旧验证码

预期：

- 图片可见且新 ID 生效
- 旧码拒绝
- 失败有明确提示

### AUTH-002 合法注册

优先级：P0。

操作：

1. 填写新手机号、用户名、强密码、图形验证码、注册短信并同意协议
2. 注册后登录

预期：

- 账号创建一次
- 成功提示
- 可进入真实工作区

### AUTH-003 注册字段校验

优先级：P1。

操作：

1. 分别提交空值、非法手机号、1 字用户名、短密码、两次密码不一致

预期：

- 逐字段提示
- 绕过前端后后端仍拒绝
- 无脏账号

### AUTH-004 协议与隐私入口

优先级：P1。

操作：

1. 打开用户协议和隐私政策
2. 关闭
3. 未勾选协议提交

预期：

- 弹窗可读可关闭
- 必需同意项生效
- 公开内容完整可用

### AUTH-005 重复手机号

优先级：P1。

操作：

1. 使用已注册手机号再次获取注册码并注册

预期：

- 合理冲突错误
- 原账号不被覆盖

### AUTH-006 密码强度与边界

优先级：P1。

操作：

1. 测试 11/12 字符、弱密码、包含手机号、长密码及有效强密码

预期：

- 按后端 PasswordPolicy 的实际规则接受或拒绝
- 前后端文案一致

### AUTH-007 密码登录成功

优先级：P0。

操作：

1. 输入正确手机号、密码与新图形验证码登录

预期：

- 登录成功
- 进入当前用户可访问的工作区或上次项目
- Cookie 会话生效

### AUTH-008 密码登录失败

优先级：P1。

操作：

1. 分别使用错误密码、不存在账号、禁用账号及错误验证码

预期：

- 不登录
- 错误不泄露账号状态或密码
- 无成功会话

### AUTH-009 登录表单交互

优先级：P1。

操作：

1. 显示/隐藏密码
2. 回车提交
3. 快速双击
4. 切换短信/密码标签

预期：

- 切换正常
- 提交期间禁重复
- 没有重复跳转和旧错误残留

### AUTH-010 记住手机号

优先级：P1。

操作：

1. 勾选记住手机号登录
2. 退出重开
3. 再取消并登录

预期：

- 仅记住手机号
- 不保存密码
- 取消后清除已记住手机号

### AUTH-011 短信登录

优先级：P0。

操作：

1. 获取 LOGIN 验证码
2. 正确输入
3. 登录后刷新

预期：

- 真实发送并正确登录
- Cookie 有效

### AUTH-012 短信失效与重用

优先级：P1。

操作：

1. 使用错误码、过期码、已使用码
2. 切换手机号后用旧码

预期：

- 全部拒绝
- 验证码一次性且绑定手机号

### AUTH-013 短信用途隔离

优先级：P0。

操作：

1. 把 REGISTER 验证码用于 LOGIN/重置密码/改手机号

预期：

- 不同用途不能混用

### AUTH-014 短信倒计时与限流

优先级：P1。

操作：

1. 重复点击发送
2. 60 秒内重发
3. 超过手机号/IP 配置限额

预期：

- UI 倒计时有效
- 后端独立限流
- 到期后可恢复

### AUTH-015 找回密码

优先级：P0。

操作：

1. 打开找回密码
2. 完成图形码、PASSWORD_RESET 短信与新密码
3. 重新登录

预期：

- 新密码有效
- 旧密码失效
- 页面可返回登录

### AUTH-016 找回密码错误路径

优先级：P1。

操作：

1. 空手机号、错误验证码、密码不合法、验证码重放

预期：

- 请求被拒绝
- 密码不被修改

### AUTH-017 登录失败限制

优先级：P1。

操作：

1. 按配置连续错误登录达到阈值
2. 等待窗口或用合法恢复流程

预期：

- 有效限流/锁定
- 无无限尝试
- 其他账号不过度受影响

### AUTH-018 刷新和新标签会话

优先级：P0。

操作：

1. 登录后刷新、复制项目链接到同浏览器新标签

预期：

- 登录状态恢复
- 数据不串账号

### AUTH-019 未登录路由

优先级：P0。

操作：

1. 无 Cookie 直接访问每类工作区/项目深链接

预期：

- 跳转登录或 API 401
- 无保护数据闪现

### AUTH-020 会话过期

优先级：P1。

操作：

1. 在 QA 缩短会话时限或使测试会话过期
2. 操作保存

预期：

- 重新登录提示
- 不误显示保存成功
- 草稿策略明确

### AUTH-021 退出登录

优先级：P0。

操作：

1. 从用户菜单退出
2. 后退
3. 再次访问 /auth/me
4. 重放旧 Cookie

预期：

- 会话与认证失效
- 不能靠后退或旧 Cookie 继续访问

### AUTH-022 多会话上限

优先级：P1。

操作：

1. 同一测试账号建立超过配置上限的独立浏览器会话

预期：

- 按策略拒绝或踢出旧会话
- 无无限有效会话

### AUTH-023 CSRF 正常流程

优先级：P1。

操作：

1. 登录后保存配置
2. 观察 XSRF-TOKEN 与请求头

预期：

- 合法写请求成功
- token 自动获取
- Cookie 不泄露密码

### AUTH-024 登录后工作台失败

优先级：P1。

操作：

1. 在登录成功后阻断工作区列表请求
2. 恢复再进入

预期：

- 显示工作台打开失败
- 不假称登录失败
- 可恢复
