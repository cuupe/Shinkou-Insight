建议归档只读、删除不可访问；对共享资料编辑可采用成员协作或创建者/管理员管理，但必须明确选定并对 UI/API/检索/下载/缓存一致验证。未确定规则时 SEC-003/PRJ-006 记阻塞。

## 2. 接口每行的四个子项

在 Excel 的“实际结果”按下列格式记录，每个子项有独立证据。单项失败则整行失败；缺一项则不能整行通过。

```text
API-B-001.N 正常：账号 C，QA-A/P1，HTTP 200 / code SUCCESS，实际列表 __，证据 __
API-B-001.A 鉴权：无 Cookie，HTTP __，无数据/副作用 __，证据 __
API-B-001.X 范围：账号 D 或 workspace/project/object 错配，HTTP __，无数据/副作用 __，证据 __
API-B-001.V 参数：不存在 ID/空值/非法类型/越界，HTTP __，合理错误且无副作用 __，证据 __
```

公开登录/注册/验证码项不要求合法 Cookie 的 A 子项，改测验证码、限流和非法请求；内部 AI/回调 A 子项改为无 key/错误 key；没有对象 ID 的 runtime/list 项 X 子项改测响应脱敏、访问范围与网络暴露。
POST/PUT/PATCH/DELETE 的正常子项必须回读前后数据，任务提交追踪最终结果，删除验证剩余关联与缓存。重复请求的 HTTP code 可以按设计不同，但不能产生重复费用、孤儿数据或终态回退。
接口负例在 QA 执行，若需要技术工具、合法回调结构或数据库准备，可只记录阻塞并把编号交给我；不要对真实业务数据修改 Cookie/ID 做实验。

## 3. P0、未知和缺失的判断

- P0 用例不适用不会在验收表中抵消尚未通过数；要通过具体发布范围决定与最终证据复核处理。
- 不存在 ID 404 是正常负例，不是接口失败；跨权返回了他人内容，即使 200/列表为空的其他情况正常也仍判失败。
- 空数组只证明这次响应没有行，不能证明已经做权限校验；写请求、导出、SSE、原文和缓存必须单独验证。
- 源码未实现但 UI 宣称生效的配置，记录功能缺口；数据不足不能用模拟响应证明生产流程通过。
