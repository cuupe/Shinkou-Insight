# 智能体语义决策与执行协议

## 唯一决策层

聊天和研究报告统一使用 DecisionEngine。原有按关键词、标点、字数判断策略、联网、图谱、变量绑定和文件格式的入口已移除。AUTO、REACT、PLAN_AND_SOLVE 和 REFLECTION 是模型理解的用户偏好，共用同一证据账本和预算。

每轮模型返回经过 Pydantic 校验的 AgentDecision：任务理解、公开解释、证据需求、来源评估，以及 execute / answer / clarify。简单回答可在第一次决策中完成。公开说明由模型实际生成，不代表供应商完整的私有思维链。

```text
对话 + 项目背景 + 当前时钟 + 证据与执行记录
  -> 模型判断需求和下一步
  -> 权限、来源类型、输入出处、重复、预算检查
  -> 按需执行工具并记录结果
  -> 模型重新判断覆盖与缺口
  -> 原文支持检查 / 必要的独立语义复核
  -> 发布答案、采用的引用、报告和文件
```

## 执行约束

- 工具意图必须包含目的和关联的缺失需求。工具可用不表示必须使用；用户关闭联网后模型无法开启它。
- 基于项目资料的需求不能任意改用网页或图谱。来源选择、时间解释和查询改写由语义决策完成。
- 每个实际工具调用只有一个 callId 和一组开始/终止事件。空结果、失败、已阻止、已复用分别记录。
- 参数归一化与缓存阻止精确重复；来源身份由类型、资产/URL、切片和内容确定，检索排名 E1 不会覆盖另一轮不同资料。
- 连续两轮没有新增证据或计算结果时收束。工具预算耗尽后继续组织受限答案，不以调用上限异常直接终止回答。决策轮数和格式修正也有上限。
- 独立需求可并行，共用预算；依赖资料的计算须等待。multiAgentMode=ON 增加独立答案复核任务。
- Calculator 使用安全 AST 与精确分数运算；表达式、变量和中文数值必须由原文提供。多字符变量名保留为完整标识符，乘法必须明确写出，程序不猜运算或变量绑定。
- 来源非空不等于覆盖。只有核对并被最终采用的资料进入引用面板；事实引文必须逐字存在于对应来源中。
- basis 区分给定材料、现实状态、派生计算、用户或系统上下文。材料收费规则与派生金额不会被误当作须联网核验的新报价。
- 计划明确只剩派生计算时，计算成功后直接撰写并复核答复，不再多请求一次规划 JSON。答复阶段没有工具访问权限。
- 当前事实需要语义时效评估和本轮读取的有效正文；历史查询保留指定区间。实际日期以服务时钟和时区为准。
- 算术组合、当前事实、显式复核及模型提出的检查使用独立 AnswerAudit；不通过时受限修正，不先发布未经核验初稿。
- 检索排序仍使用向量/词法 IR。词法分数校准和来源多样性属于召回排序，不作为用户意图或工具调用的判定器。本地哈希向量不是语义 Embedding。

## 模型与输出预算

decisionReasoningEffort 默认 none。模型仍返回公开决策解释；该设置只控制供应商额外推理。页面可明确开启额外推理，其强度独立传入协议模型。Qwen 实际验证中额外推理曾长时间没有有效协议输出，因此不默认开启。

decisionTimeoutSeconds 为独立的模型响应预算，配置默认 180 秒；聊天协议每次请求最多 90 秒，研究协议尊重配置、最多 600 秒。HTTP 研究决策收到正文后，可使用 researchCompletionGraceSeconds 指定的一次固定完成宽限，默认 120 秒，单次请求的基础预算与宽限合计仍不超过 600 秒。宽限不因新片段反复延长，不向聊天、独立复核、受限修正、仅有私有推理或无响应的请求授予；首响应、断流和整轮预算仍独立执行。进度展示当前阶段上限，进入宽限后明确提示；超时错误保留已接收字数但不发布半截响应。

chatTimeoutSeconds 默认整轮 180 秒、researchTimeoutSeconds 默认 600 秒，涵盖工具、模型和受限修正，不在重试或进入下一个阶段时重置。主动暂停的等待不计入预算。等待期间每 10 秒更新同一阶段的实际等待时长、阶段上限和整轮剩余时间，支持取消；预算结束后保留具体失败阶段。

HTTP 协议首响应默认等 25 秒，响应流无内容/推理更新默认等 20 秒。仅在没有任何内容或推理的首响应停滞时，取消原连接并最多恢复一次，遵循原请求总预算及供应商重试设置。收到半截输出后不得恢复并拼接；鉴权、限流和格式错误不走首响应恢复。公开错误分别记录 MODEL_FIRST_RESPONSE、MODEL_STREAM_IDLE、MODEL_RESPONSE_BUDGET 与 RUN_TIME_BUDGET。ModelChatResult.responseStats 和完成指标记录首响应耗时、恢复次数和总响应耗时；发生恢复时总 usage 不声明完整。

普通对话、写作、稳定常识与基础数学恒等式使用 general 依据，可在一次决策中直接回答。引用要求按每条 claim 及其关联需求判断；无关附件和同一回答中的其他资料不会把一般解释变成必须引用的断言。关联的材料、现实核验、计算、上下文需求仍须提供支持；把 claim 标为 general 不能绕过关联需求。用户明确要求查证时按 world 核验，当前事实不能降为 general。

包含材料、给定上下文、计算或现实核验的答复进行独立语义复核，检查正文是否与 claims、原文及用户条件一致。混合问题可以完成有依据的部分，并准确说明另一部分的缺口；来源冲突不能任选一份作为确定结论。复核不要求一般解释和创作伪造引文。

同一需求的后续更新只覆盖明确提交的字段，保留原先的来源、时效区间和依据类型。clock 引文校验使用实际送入模型的时钟快照，避免模型等待期间时间变化造成假阴性。连续两次答案修正仍失败时通常产生 ANSWER_VALIDATION，保留具体问题和重试建议，不返回“知识库没有资料”的错误结论。仅当已成功执行知识库检索、候选全部为零、没有任何证据或检索故障，且仍有缺失的内部材料需求时，丢弃未通过的草稿，改为明确请求补充资料；执行正常完成但 reviewResult.approved=false，不将资料缺口视为验收通过。未执行检索、无关但非空的候选、权限阻断、协议错误和超时均不能触发此处理。

关键条件歧义与执行故障分开处理。AnswerAudit 可选择 revise 修正事实错误，或 clarify 提出具体缺失条件；后者生成正常完成的澄清答复，保留原有执行决策并增加复核后的澄清记录，不反复改写同一个假设结论。明确标注假设、算术正确的条件分支可以通过复核，缺少唯一结论的条件仍为 missing。按人、房、层、次数计费等含义由模型结合原文判断，不使用词表分流或默认行业惯例。

AnswerClaim.kind 区分确定事实、条件结果与缺口说明。整体需求的 missing 状态不阻止其中已有原文支持的部分事实；条件结果须明确 assumptions，缺口说明不要求伪造“未提供”的原文引句。这两类答复必须经过独立语义复核，检查正文、输入、算术和条件，不凭类型标签免除事实核验。实际给出的引文仍逐字校验，未核验的现任身份不能用 conditional/limitation 标签绕过复核。

复核的 unresolved_conditions 记录确实会改变结果的未确认条件。即使条件计算通过复核，条件说明也由系统放在答复开头，保留有条件的计算并提示确认，不把文末的假设说明用作开头确定结论的补救。该列表由语义复核产生；不同解释不影响结果时为空。

trustedUserSources 为用户原话提供 U1 等本轮来源编号，便于跨轮逐字引用价格、数量和新确认的规则；助手的历史回答不进入该来源表。来源内容按预算限制，编号保留。计算校验反馈具体缺失数值和无效引句，帮助决策修正输入；连续输入校验受阻则产生 CALCULATION_INPUT，不能称为知识库资料不足。

报告将实际检索的 evidence_ids 与用户/项目输入的 context_source_ids 分开。历史模型输出若把本轮真实 U1 或 project.name 等编号放入 evidence_ids，执行器将其归入输入来源；未知编号仍被阻断。研究报告附加“输入来源与核验范围”，展示实际采用的输入编号与经过逐字核对的引句，不计入知识库引用数量。用户给定日期可以支持明确说明首尾计数方式的条件性时长计算，不能证明实际执行周期或批准验收；有效 U1 也不能因缺少知识库 E 编号被一律否定。现实世界的当前事实仍须独立来源与时效核验。

运行故障只在对应消息的失败卡片展示，细节可展开。输入区仅展示输入或操作错误；旧消息正文内与错误元数据完全一致的错误串不再重复渲染，已有部分答复保留。刷新与恢复运行使用同一展示规则。对话标题明确区分“上次运行未完成”“待你确认条件”和已就绪。

协议输入按完整请求计数，包括系统规则、实际阶段 schema、服务端时钟、状态 JSON、历史与输出预留，并留出传输/协议修正余量。16K 应用偏好只限制可选历史，不再把复核状态硬分配为约7.3K。完整报告、claims、已引用原文、已引用的用户输入和项目约束不截断；必要资料超过应用偏好时，在本轮配置的真实模型窗口内借用预算。先压缩未采用候选预览、重复工具结果和旧历史，不因报告变长直接阻断复核，也不省略必需证据后宣称复核通过。

被引用来源的完整正文保留至复核，不再先截成6000字符导致尾部引句或限制丢失。确实无法容纳完整必需输入时，以当前阶段返回 CONTEXT_BUDGET，说明估算输入、可用输入和模型窗口；模型不接收半截报告，不发布未复核正文。复核准备完成事件和 decisionMetrics.contextBudgets 记录仅含数量的预算信息，便于区分应用分配问题与真实窗口不足。结构化响应允许合法重复字段和原文引文，仍限制长度并校验 schema。普通文本的异常重复保护保留。

执行工具的决策只需给出需求变更和工具参数，不预写答案；研究模式的完整 Markdown 报告只在 answer 中生成一次，服务端将复核后的正文保存为报告。无需再在 report 重复生成一份相同正文；旧协议返回的 report 仍兼容。正文中的事实、计算、引用与 claims 仍进行相同的确定性检查和独立复核。

HTTP 决策与复核增量接收供应商响应，完整 JSON/schema 校验通过后才向执行器交付对象。结构化响应中，一个完整且合法的 JSON 对象本身可作为完成边界；普通文本仍要求供应商完成标记。接收期间只公布响应字符数、实际等待时间和上限，不公布私有推理或未校验的答案。未完成、截断、异常重复或传输失败保留准确阶段。
硅基流动的决策、受限修正和独立答案复核使用 response_format=json_object；保留完整 schema 提示和本地 Pydantic 校验，temporalChecks 仍为必需字段。其他结构化协议可使用 json_schema。该选择由协议类型定义，不依据用户措辞分流。schema 去除展示标题和默认值说明时保留 properties/$defs 中真正的字段名。每条决策证据正文最多预览 500 tokens，原始全文仍保存在来源账本供逐字引文核对，未读取的搜索摘要仍不能充当正文。JSON/字段校验失败记录位置和错误类型，不把原始响应或私有推理写入公开错误。

时间含义由模型按语义填写 timeScope：as_of 表示 dateTo 时点的状态核验，官方当前名单不需要在查询当天发布；period 表示 dateFrom/dateTo 范围内的事件，区间外或日期不明的报道不能证明该区间事件。supportsCurrent 专用于状态持续有效的判断，不要求历史事件声明“仍在发生”。本轮读取日期、正文和语义复核仍是必要门槛；旧缓存保留原读取日期。
period 事实断言可填写 eventDateFrom/eventDateTo；实际发生日期与正文用途由独立复核判断，不按父需求编号强制把每条背景断言当成近期事件。AnswerAudit.temporalChecks 必须逐项给出对应断言、实际发生范围和依据。disposition=event 时程序检查复核覆盖与日期范围相交；background 须由复核确认其确为背景，并提供逐字存在于答案中的 answerExcerpt 定位。旧事充当近期事件仍被阻止，不从词表猜事件或背景。该机制避免已明确作背景的上半年销量触发无意义修正。
period 不要求文章的发布日期也在事件区间内，例如今天发布的明天预报；事件日期以原文的独立复核结果为准。一般资讯请求未指定范围时先选择并说明合理默认范围，近期舆情默认最近30天，无需为这个范围单独中断任务询问。
带发布日期的 as_of 报道使用30天的保守时效门槛，不能把一年前的任命新闻因当天抓取而变成现任证明。没有发布日期的实时状态页面依赖正文和页面用途的语义复核。规划默认 none 额外推理，独立复核默认 low 且思维预算256 tokens；语义复核、逐字引文、计算与日期检查仍执行，调用方可明确配置其他预算/等级。复核输出预算依据断言和需求数量计算，遵循所选模型输出上限，不修改原始生成配置。

独立 AnswerAudit 可以在一次复核中返回 correction（AnswerRevision），明确核验修正后全文、断言与条件；程序再次校验其真实来源、逐字引文和 temporalChecks，均通过才采用。修正稿不能调用工具或引入未读取来源，检查失败则回滚需求与来源更新，不能发布该稿。该路径减少额外修正和重复复核两个串行请求。

机械检查阻断或复核未能直接修正时，保留独立 AnswerRevision 受限修正路径，仅修正答案、断言及必要的需求/来源判断，不再次输出整套工具规划；修正阶段没有工具权限，最多一次受限修正后复核，响应上限 90 秒。修正失败时保留具体错误，不把旧事件伪装成近期事件，也不把服务失败称作资料不存在。已读取网页的页面标题可作为原文引句，仍必须通过正文语义复核。

search_web 可由决策模型明确指定 publishedFrom/publishedTo，用于用户任务要求的出版时间区间。执行器按已有发布日期机械筛选，记录过滤范围和排除数量；不根据问题词语推断该范围。没有明确出版范围时保留原逻辑，包括旧文章对未来事件的有效预报；实际事件日期仍由独立复核判断。

供应商发送 finish_reason 或结构化完整 JSON 对象到齐后，SSE 最多再等两秒接收用量，避免缺少 DONE 或连接未关闭导致完整响应被误判超时。若完整 JSON 已收到、仅等待用量时触及请求总上限，仍将该完整对象交给 schema 校验，用量标为 unavailable。无完整对象的半截输出仍拒绝；未取得真实用量时标为 unavailable，不伪造估算值。

规划模型省略可选来源评估不等于引文无效。原文匹配只检查真实来源与逐字引文，明确判定无关的来源仍被阻止；独立复核负责判断正文相关性、覆盖与时效。复核通过后将实际采用的来源及复核理由写回公开账本，保证最终引用面板与答案一致。

已存在的需求可仅返回 id/status/evidenceIds，保留原 description、依据和日期；新需求仍必须说明含义。rationale 可省略与 summary 重复的说明，公开账本保留实际决策理由，减少重复生成。

逐项日期复核不只依赖规划者填了哪些 claims：每个已覆盖的现实区间需求都必须有正文事实的 temporalChecks，缺少覆盖不能仅凭 approved=true 放行。持续议题需有原文依据，不能把发布日或首次发生日直接解释为持续至今。复核完成事件保存实际日期检查与是否修正，供诊断和历史回放。

## 可观测性

### 答案复核的协议恢复

复核响应的预算同时考虑断言、需求和可能返回的修正正文，默认预留至少 2048 tokens，但始终受所选模型输出上限约束。不能仅按断言数量压缩预算，同时又要求返回完整修正稿。

完整响应的 JSON / 字段 / 动作一致性错误，以及供应商明确返回的输出截断，最多触发一次复核协议修正。修正只重审原草稿与原证据，不重新规划或调用工具，不拼接和发布失败响应；仍使用原轮次总时间预算。执行记录中的 node.updated 会注明 protocolRepair 和原因。连续两次失败仍按失败处理，不能把协议恢复当作事实复核通过。

模型明确达到输出上限时使用 MODEL_OUTPUT_LIMIT，未收到完成标记的断流使用 MODEL_STREAM_INTERRUPTED；字段缺失仍提供安全的字段路径提示。连接、鉴权和超时故障不作为格式问题重试。错误提示不包含原始模型响应或凭据。

原草稿已在准确请求澄清时，复核应检查缺口描述和事实边界，无需再生成相同的澄清稿。一次无关检索不能证明整个知识库缺少资料，项目成功指标也不能视为已实现的效果。

复核的“通过”与“下一步动作”不再通过互斥字段组合导致整轮协议失败。clarify 动作优先：即使模型同时填写 approved=true，也按未批准原结论处理并展示具体澄清问题；只有 unresolved_conditions 时用这些明确条件组织问题，两者都缺失才返回 clarification_question 的具体规则错误。

approved=false 同时提供 correction 表示尚未批准的修正提案。提案必须先通过原文、来源与日期的确定性检查，再交给第二次独立复核；不能直接发布，也不必额外调用模型重写同一份提案。直接答复和计划完成后的正文生成共用这一约束，最多两次复核，第二次仍拒绝时按上述空检索条件请求补充资料，或返回答案校验失败。事件中 correctionProposed 与 corrected 区分待核验提案和已批准修正。

decision.updated 持久化并通过 SSE 传递 resolvedGoal、summary、rationale、needs、assessments、tools、remainingToolCalls。折叠状态显示最新解释，展开后查看每轮缺口、依据和动作理由。

tool 事件包含 callId、实际状态、新增证据数、耗时和错误；run.failed.error 包含 code、stage、message、remedy、retryable。Java 与浏览器用相同事件恢复历史。供应商私有推理文本不作为公开决策保存。

完成事件的 decisionMetrics 记录决策、实际/复用/阻止/失败调用、证据、复核次数及收束原因。协议提示词和 schema 哈希进入运行快照。

浏览器每 5 秒通过有项目与用户权限检查的运行快照接口补齐 SSE 游标之后的事件。SSE 与快照按 eventId 去重；即使终态事件遗漏，也依据已持久化的状态和答复结束运行。前端事件处理异常同样关闭并结算当前请求，避免 promise 永远保持执行中。
