# 23. 上线运行与知识库配置

## 1. Token 用量统计

Agent 每次完成运行后，将提供方返回的输入、输出、总 Token 和模型名写入 `agent_token_usage`。统计接口同时提供：

- 工作区范围的项目、用户、模型明细；
- 项目范围的用户、模型明细；
- 近期开销趋势与运行次数。

没有提供方 usage 的运行不会用字符数伪造 Token。历史记录没有模型名时，界面会标记为“模型未标注”，而不是猜测模型。

## 2. 生产项目中的 Chunk 切分

上线产品通常允许管理员在知识库或项目级别调整切分参数，但不会把每一种底层算法都交给每次上传的用户选择。原因是切分规则会影响向量索引、检索质量、上下文成本和已有引用，随意切换容易造成同一项目的索引标准不一致。

当前项目配置包含：

| 配置 | 作用 | 默认值与边界 |
|---|---|---|
| 切分方式 | 自然段落与句子、优先保持段落、固定长度 | 默认自然段落与句子 |
| 每块长度 | 控制单个 Chunk 的最大长度 | 1200；允许 400–4000 |
| 上下文重叠 | 保留相邻 Chunk 的边界语境 | 180；必须小于块长度 |
| 保留标题层级 | 把章节标题带入检索片段 | 默认开启 |

保存配置后只影响新的索引任务。已有资料需要显式“重新索引”，这样用户能清楚知道什么时候产生了新的向量和引用。

## 3. 可审计界面约定

- 对话标题在首条用户消息后生成一次整理式标题，后续问题只更新预览，不覆盖标题。
- 过程回顾固定在可阅读高度内，阶段、工具、证据和结果摘要在面板内滚动；不展示模型隐藏思维内容。
- 成员列表显示加载中、失败和重试状态，路由切换后会重新读取对应工作区。
- 页面只展示后端返回的真实记录；没有数据时使用空状态，不放置演示数字。
